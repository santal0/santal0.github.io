# 第3页：Liveness Analysis - Why

## 原文翻译

问题：

* 中间表示（IR）可以使用无限数量的临时变量
* 真实机器只有有限数量寄存器

```text
源代码 → IR → 机器代码
```

---

## 内容描述

这一页解释：

为什么必须做活跃性分析。

---

## 讲解

IR里经常会出现：

```c
t1 = a+b
t2 = t1*c
t3 = t2+d
...
```

这些 `t1 t2 t3` 都是 temporary。

但真实CPU可能只有：

* x86-64：16个通用寄存器
* RISC-V：32个
* ARM：有限个

因此：

> 多个 temporary 必须共享寄存器。

而共享的条件：

# 它们不能同时活跃。

---

# 第4页：Why（继续）

## 原文翻译

* 如果 temporary a 和 b 不会同时“被使用”
  那么它们可以放进同一个寄存器。

* 因此，很多 temporary 可以塞进少量寄存器。

* 如果放不下，多余变量可以放内存。

* 编译器需要判断：
  哪些变量会同时“正在使用”。

* 活跃性分析：
  判断每个变量是否活跃。

* 一个变量是活跃的：
  如果它当前保存的值未来可能还会被使用。

示例：

```c
a = b + 1;
return a;
```

How?

---

## 内容描述

这一页正式定义：

# 什么叫“活跃（live）”

---

## 讲解

最关键一句：

> “未来可能会被使用”

例如：

```c
a = b+1;
return a;
```

这里：

* `a` 在赋值后仍然活跃
* 因为 return 会用到它

但：

```c
a = b+1;
a = 0;
return a;
```

第一条里的 `a=b+1` 就“不活跃”了。

因为：

* 旧值还没被用
* 就被覆盖了

这类值叫：

# dead value（死值）

对应优化：

# Dead Code Elimination

# 第5页：How

## 原文翻译

如何进行活跃性分析？

问题：

```text
变量 x 在语句 n 之后还会被使用吗？
```

步骤：

* 哪些语句可能在 n 后执行？
  → 构建控制流图（CFG）

* x 是否在这些语句中被使用？
  → 分析语句

* 逆向分析（Backward Analysis）
  → 从未来推回过去

---

## 内容描述

介绍核心思想：

# 活跃性分析是“逆向数据流分析”

---

## 讲解

这是重点。

很多编译器分析：

* 常量传播
* reaching definitions

是“正向”的。

而活跃性分析是：

# backward analysis

因为：

你必须看“未来会不会用”。

例如：

```c
1: a=1
2: b=2
3: print(a)
```

分析第1行：

要看后面有没有 `use(a)`。

因此：

# 信息从后往前传播。

构建控制流图：

* 节点：语句
* 边：控制流

如果语句 m 后可能执行 n：

```text
m -> n
```

形成循环。

控制流图（CFG）是：

# 所有数据流分析的基础。

因为：

变量活跃性会沿 CFG 边传播。

# 第7页：变量 b 的活跃性

## 原文翻译

变量 b 的活跃性

---

## 内容描述

课件让你思考：

变量 `b` 在哪些地方是 live。

---

## 讲解

观察：

```text
2 b := a+1
3 c := c+b
4 a := b*2
```

`b` 被：

* 第3行使用
* 第4行使用

因此：

在 2→3→4 之间：

# b 是活跃的

但：

过了第4行后：

* b 再也不用

因此变成 dead。

---

# 第8页：变量 a 的活跃性

## 内容描述

让你分析变量 `a` 的活跃区间。

---

## 讲解

注意：

```text
1 a :=0
2 b :=a+1
```

第1行定义的 a：

只活到第2行。

而：

```text
4 a :=b*2
5 if a<N
```

第4行定义的新 a：

活到第5行。

这体现：

# 同名变量不同定义对应不同 live range

这是 SSA 出现的重要原因之一。

# 第11-15页：Flow Graph Terminology

这些页是在逐步填空。

---

## 核心术语翻译

### out-edges

出边：

从当前节点流向后继节点。

---

### in-edges

入边：

从前驱节点流入当前节点。

---

### succ[n]

节点 n 的后继集合。

---

### pred[n]

节点 n 的前驱集合。

---

## 示例结果

对于节点5：

```text
5 -> 2
5 -> 6
```

因此：

```text
succ[5] = {2,6}
```

节点2的前驱：

```text
1 -> 2
5 -> 2
```

因此：

```text
pred[2] = {1,5}
```

---

## 讲解

CFG 本质上是有向图。

数据流分析本质：

# 在图上传播集合信息。

例如：

```text
out[n] =
∪ in[s]
s∈succ[n]
```

意思：

一个节点的输出活跃变量，

来自它所有后继节点的输入活跃变量。

# 第16-20页：Uses and Defs

这是活跃性分析最核心定义之一。

---

# 基本概念

## def

定义变量。

例如：

```c
a = 1
```

定义了 a。

---

## use

使用变量。

例如：

```c
b = a+1
```

使用了 a。

---

# 示例程序

```text
1 a:=0
2 b:=a+1
3 c:=c+b
4 a:=b*2
5 if a<N
6 return c
```

---

# 结果翻译

## 第17页

```text
def(3) = {c}
```

因为：

第3行给 c 赋值。

---

## 第18页

```text
def(a) = {1,4}
```

因为：

第1和4行定义了 a。

---

## 第19页

```text
use(3) = {b,c}
```

因为：

```text
c := c+b
```

右边用了 b,c。

---

## 第20页

```text
use(a) = {2,5}
```

因为：

* 第2行使用 a
* 第5行判断 a<N 使用 a

---

# 讲解

这是整个数据流方程基础。

后面所有公式都基于：

```text
use[n]
def[n]
```

# 第21页：Liveness 正式定义

## 原文翻译

### Live-in

如果变量在某节点任一入边上活跃，

则它在该节点 live-in。

---

### Live-out

如果变量在某节点任一出边上活跃，

则它在该节点 live-out。

---

定义：

```text
in[n]
```

节点 n 的 live-in 集合。

```text
out[n]
```

节点 n 的 live-out 集合。

---

变量在一条边上是活跃的：

如果：

存在一条从该边到变量 use 的路径，

且中间没有经过新的 def。

---

含义：

* 变量未来会被使用
* 且在使用前不会被重新定义

---

## 内容描述

这是整章最重要定义。

---

## 讲解（非常重要）

这是活跃性的本质：

# “当前值未来还能不能活着到 use 点”

例如：

```c
1 a=1
2 a=2
3 print(a)
```

第1行定义的值：

到不了 use。

因为：

第2行重新 def 了 a。

所以：

第1行定义的值 dead。

---

## 活跃性核心数据流方程

这一页实际上已经隐含了：

```text
in[n] = use[n] ∪ (out[n] - def[n])

out[n] = ∪ in[s]
          s∈succ[n]
```

这是编译器课程必须掌握的经典方程。

# 一句话理解活跃性分析

你可以把它理解成：

> “一个变量当前保存的值，
> 会不会在未来某处被真正使用？”

如果不会：

# 它已经死了（dead）

编译器：

* 可以覆盖它
* 可以释放寄存器
* 可以删掉相关代码

这就是现代优化编译器的重要基础。
